# 법인·팀 매핑 데이터

`corp_team_mapping.csv`는 뉴스 검색 대상과 팀 분류에 사용하는 기준 파일이다. 모듈 2는 실행할 때 이 파일을 직접 읽는다.

이 파일은 공개 코드 저장소에 두지 않는다. 비공개 데이터 저장소(`YUJAEYUN/corp-issue`)의 같은 경로에 있고, 워크플로가 실행할 때 이 위치로 복사한다. 아래 갱신 절차의 명령은 데이터 저장소에서 실행한다.

## CSV 형식

| 열 | 내용 | 예시 |
|---|---|---|
| `corp_name` | 관리 리스트의 법인명 | `예시법인` |
| `team` | 담당 팀 번호 | `1` |

한 행은 법인과 팀의 조합이다. 한 법인이 여러 팀에 속하면 팀마다 한 행을 둔다. 별칭과 `_FOF` 제거명은 모듈 2에서 계산하므로 CSV에 추가하지 않는다.

## 현재 데이터

2026-09-17 기준으로 447행, 고유 법인명 429개가 있으며 17개 법인이 여러 팀에 속한다.

현재 파일은 담당자가 거래 실적 조건으로 선별해 전달한 목록이다.

## 갱신 방법

1. 업무망 Excel에서 [모듈 1](../../module1_vba_generator/README.md)이 생성한 매크로를 실행하고, 즉시 창의 팀별 목록을 복사한다.
2. 복사한 텍스트를 조직의 승인된 파일 전송 절차로 인터넷망에 옮긴다.
3. 팀별 목록(`1팀 (N건) - 법인A, 법인B, ...`)을 `corp_name,team` 형식으로 풀어 데이터 저장소의 `data/corp_team_mapping/corp_team_mapping.csv`를 교체한다. 한글 법인명이 깨지지 않았는지 확인한다.
4. 아래 명령으로 형식과 변경 내용을 확인한다.

   ```bash
   python3 data/corp_team_mapping/validate.py
   git diff -- data/corp_team_mapping/corp_team_mapping.csv
   ```

5. 추가·제외된 법인과 팀 배정이 맞으면 데이터 저장소에 CSV를 커밋한다. 데이터 저장소는 비공개라 커밋 메시지에 법인명을 적어도 된다.

   ```bash
   git add data/corp_team_mapping/corp_team_mapping.csv
   git commit -m "법인 리스트 갱신 (YYYY-MM-DD)"
   ```

Python은 UTF-8과 UTF-8 BOM 형식을 읽을 수 있다. 다른 인코딩으로 받은 파일은 교체 전에 변환한다.

## 검증 범위

검증 스크립트는 다음 항목을 검사한다.

- 팀 번호가 허용 범위 안에 있는지
- 같은 법인·팀 조합이 중복됐는지
- 설정에 등록된 제외 라벨이 포함됐는지

법인의 실제 존재 여부와 현재 거래 상태는 자동으로 판단하지 않는다. 담당자가 원본 Excel과 대조해야 한다. 과거 추출 결과에 포함된 소계 라벨 `수익`은 제외 대상으로 관리한다.

변경 이력은 Git으로 관리한다. 별도 diff 스크립트와 웹 관리 UI는 제공하지 않는다.
